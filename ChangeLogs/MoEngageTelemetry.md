# 16-09-2026

## 1.0.0

- Added MoEngageTelemetry module. Spans can be opened backdated to a caller-supplied anchor, and data-tracking opt-out no longer gates recording. Completed metrics now persist to storage (gated on SDK-disabled per spec: no new storage or network while disabled; existing data survives) and upload through two triggers — pending count crossing `t_e_b_s`, and the `t_e_f_i` window elapsing at start. Backgrounding lands in-memory metrics on disk before the process suspends, but does not batch or upload. Sampling decisions are logged per operation (kept, dropped, and the budget that decided it). Session sampling caps (`t_s_d`/`t_s_t_e_c`/`t_s_f_e_c`) are enforced at batch build, failures prioritised slowest-first; a chunking fix seals a trailing chunk of exactly `t_e_b_s` metrics as full rather than misclassifying it as leftover. A failed initialisation (instance torn down before start) replays as a failed `init` span and is persisted directly to the workspace store, including on a never-synced workspace. Also ships a coordinated app-group extension-metrics store (`persistToExtensionMetrics`/`drainExtensionBatch`) whose foreground-drain wiring lands with the push-telemetry follow-up. Sampling now counts a metric whose operation succeeded but which lost a checkpoint as a failure when choosing what to keep, so a degraded operation no longer has to be the slowest of its window to be reported; the metric itself is unchanged on the wire — this only decides selection. A storage-encryption change now reaches every telemetry file immediately: cleanup and migration run when a file is read, and these files are otherwise untouched until the next batch build, so a stale encrypted copy could outlive the switch
